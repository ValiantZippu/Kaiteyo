# Kaiteyo — Product Overhaul Backlog (spec-derived)

> Consolidated, actionable backlog derived from the four product directives:
>
> 1. **Core Intelligence Overhaul** — dictionary/search/knowledge-graph/learning platform (spec §0–§204)
> 2. **Complete UI/UX Audit, Revamp, Debug Panel & Page Identification** (product-wide interface overhaul)
> 3. **Media Center Forensic Audit & Rebuild**
> 4. **World System** — 3D world engine, Japan-scale map, streaming, vertical slice
>
> This file turns those directives into the project's planning system: it maps what the
> directives asked for onto **what the repository already has**, then defines new work
> items (KT-* IDs) only for the **genuine gaps**. Where a task already exists in
> [`MASTER_TODO.md`](MASTER_TODO.md) or is already done, it is **cross-referenced, not
> duplicated**. Nothing here is "DONE because a button exists" — see
> [Definition of Done](#6-definition-of-done).
>
> Status legend: ✅ `DONE` · 🚧 `IN PROGRESS` · 🔬 `TARGET` (architected/documented, not
> built) · 📋 `PLANNED` · 🔍 `RESEARCH` (needs investigation) · ⛔ `BLOCKED` ·
> 💀 `PLACEHOLDER` (scaffold, not functional).
>
> Priority legend: 🔴 P0 critical · 🟡 P1 high · 🟢 P2 medium · 🔵 P3 low.
>
> **ID scheme** (extends [`MASTER_TODO.md`](MASTER_TODO.md)): `KT-<AREA>-<NNN>`.
> New areas introduced by the overhaul directives: `NAV` (navigation shell), `THEME`
> (theme/tokens), `DEBUG` (page identity + debug tooling), `CARD` (card registry),
> `LEVEL` (level profiles), `SEARCH` (universal search), `GRAPH` (knowledge graph),
> `RAD` (radical/component explorer), `SENT` (sentence system), `DATA` (frequency /
> keyword / data provenance), `AI` (generated content), `UI` (cross-screen UX audit),
> `DOC` (overhaul documentation), `TEST` (overhaul test suites).

## 6. Definition of done

A backlog item is DONE only when **all** of the following hold (spec §155, §200):

- Implementation exists (not a shell, not a button that does nothing).
- Integration exists (wired into real state/navigation/persistence).
- UX exists (usable by the intended input methods; no ghost controls).
- Persistence works where applicable (settings survive restart).
- Error/empty/loading states exist where applicable.
- Tests exist where appropriate and pass (`:core:allTests`, `:desktopApp:compileKotlinJvm`,
  `:desktopApp:test` per area).
- Documentation reflects the change (`CURRENT_ISSUES.md`, `CHANGELOG.md`, subsystem docs).
- No obvious placeholder behavior remains.

Never mark an item DONE because code compiles or a screen opens. Build success is not UX
success (spec §46).
