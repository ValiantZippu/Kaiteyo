# Privacy

This document states what Kaiteyo **actually** stores and transmits, based on the code.
Kaiteyo makes no privacy guarantees beyond what is described here — there is no central
service, but several **opt-in** features do connect to third-party services.

## What stays on the device (always)

- All study data: decks, cards, FSRS scheduling state, review history, statistics,
  achievements, tags, flags, suspend/bury state, writing-evaluation results
- All settings and preferences (DataStore / `settings.json`)
- Imported dictionaries and their indexes (desktop)
- Media metadata, bookmarks, subtitles (desktop)
- Mined cards, OCR history, browser history, activity log (desktop)
- Backups you export

None of this is sent anywhere unless you use the sync feature (below).

## What leaves the device (opt-in only)

| Feature | Data transmitted | When | Destination |
|---|---|---|---|
| **Sync** | A backup snapshot of your study data (decks, cards, SRS state, history) | When you sign in with GitHub and enable sync | Your **private** GitHub gist |
| **GitHub account** | OAuth device-flow: the app receives scoped access tokens used for the gist | When you sign in | github.com |
| **Update checks** (desktop) | App version + platform, to fetch the update feed | When auto-update is enabled | GitHub Releases (`update-feed`) |
| **First build (developers)** | None of your data — downloads the bundled dictionary DB + TTS voices | First build when assets are missing | GitHub Releases |
| **Firebase (Android `googlePlay` flavor only)** | Analytics events + crash reports (Firebase Analytics/Crashlytics) | While using the googlePlay build | Google Firebase |
| **Play billing/review** (Android `googlePlay` only) | Play Billing + in-app review data | When using sponsor/review flows | Google Play Services |
| **TTS (desktop)** | None — voices are bundled | — | — |
| **OCR** | None — runs locally (Tesseract) | — | — |
| **AnkiConnect / local API / text hook** | Localhost only | When configured | your machine |

The F-Droid Android build and the desktop app (outside opt-in sync/updates) do **not**
integrate Firebase or any analytics.

## Account data

- Kaiteyo hosts **no accounts**. "Account" = your GitHub account, used solely for the
  private-gist sync transport.
- OAuth tokens are stored locally (in the desktop app's token vault); revoking the GitHub
  app/gist stops sync.

## Analytics & crash reports

- **Google Play flavor only**: Firebase Analytics and Crashlytics. The F-Droid flavor and
  all other platforms have none.
- Analytics can be disabled in the app's Analytics settings category (Google Play flavor).

## Dictionary downloads

- Bundled data ships with the app (generated by KJD from openly licensed datasets — see
  `../data/SOURCES.md`).
- User-imported dictionaries never leave the device.

## Third-party services summary

| Service | When used | What it sees |
|---|---|---|
| GitHub (OAuth + gist) | Sync enabled | Your token scope, your private gist content |
| GitHub Releases | Update checks / first build | App version, platform; downloads assets |
| Firebase (Google Play only) | googlePlay builds | Analytics/crash data |
| Google Play Services (Google Play only) | googlePlay builds | Billing/review data |

## Guarantees (and non-guarantees)

- ✅ No telemetry in the F-Droid build, iOS, desktop (outside opt-in sync/updates), or
  core engine.
- ✅ Study data is yours: export/import, backup, Anki interop.
- ⚠️ **No end-to-end encryption** of synced data — a private GitHub gist is protected by
  your GitHub account, not by Kaiteyo.
- ⚠️ **No encryption at rest** on local files.
- ⚠️ If you use the local HTTP API, a bearer token protects it — but anything on localhost
  shares your machine's trust boundary.
