# Data Architecture

This document describes where Kaiteyo's data lives, what technology stores it, how it is
versioned and migrated, and which category each piece of data falls into
(bundled / downloaded / generated / user-created / cached / synced).

## Storage technologies

| Storage | Where it is used | Notes |
|---|---|---|
| SQLDelight `AppDataDatabase` | `core/` — the bundled language database | Read-only at runtime; generated offline by the KJD pipeline; `linkSqlite = true` |
| SQLDelight `UserDataDatabase` | `core/` — all mutable study data | Versioned schema with `.sqm` migrations |
| DataStore Preferences | `core/.../user_data/preferences/` | App settings, theme, practice preferences |
| JSON files on disk | `desktopApp/.../desktop/` | Desktop suite state under `~/.kaiteyo/`: `library/cards.json`, `settings.json`, `window.json`, `history.json`, `dictionaries/`, `index/`, `anki-media/`, `ocr/` |
| System keychain / file | `desktopApp/.../engine/account/` | GitHub OAuth token (`TokenVault`) |
| SharedPreferences | Android | Android platform preferences + transfer-file grants |

## The two databases

### AppDataDatabase (immutable, bundled)

- SQLDelight schemas in `core/src/commonMain/sqldelight_app_data/` (`Letters.sq`, `Vocab.sq`).
- Bundled with the app as a prepared SQLite asset (`kanji-dojo-data-base-v15.sql`,
  `AppDataDatabaseVersion = 15` — see `buildSrc/.../AppAssets.kt`).
- **Never written at runtime.** The app opens it read-only; a corrupt/missing bundled
  database is replaced with a fallback (iOS) or reported.
- Content is generated by the **KJD pipeline** (`kjd/`) from openly licensed datasets —
  see [`SOURCES.md`](SOURCES.md).

### UserDataDatabase (mutable)

- SQLDelight schemas in `core/src/commonMain/sqldelight_user_data/`
  (`UserData.sq`, `UserData_enhancements.sq`, `UserData_statistics.sq`).
- Schema migrations live in `core/src/commonMain/sqldelight_user_data/migrations/`
  (`1.sqm` … `14.sqm`), applied through `UserDataDatabaseMigrationProvider` platform
  actuals and the `UserDataDatabaseMigrationAfter*` classes.
- Holds: decks (letter/vocab), cards, FSRS scheduling state, review history, practice
  settings, statistics records, text-analysis data.

## Versioning & migrations

- **App data version** is a build-time constant (`AppDataDatabaseVersion`); the asset is
  versioned (`...-v15.sql`) and downloaded by Gradle on first build if missing.
- **User data schema version** is tracked by SQLDelight migrations (`1.sqm` … `14.sqm`).
  Migration strategy is "after-N" incremental Kotlin migrations plus `.sqm` SQL files.
- **KJD database schema** (`kjd/.../db/Schema.kt`) is independently versioned
  (`meta.schema_version`); incremental **patch updates** (base DB + delta) are applied by
  the desktop app via `kjd`'s `DatabasePatcher`/`DatabasePatch` (`KjdDatabaseUpdater`).
- Never change the SQLDelight `.sq` schemas without an explicit request — see
  `development/AI_CONTEXT.md` ("never change" list).

## Where persistent data lives (by platform)

| Platform | App data (bundled) | User data | Desktop suite |
|---|---|---|---|
| Windows | inside install dir / app data | SQLDelight DB in app data | `%LOCALAPPDATA%\Kaiteyo`, `~/.kaiteyo` |
| macOS | inside app bundle | app data dir | `~/Library/Application Support/Kaiteyo`, `~/.kaiteyo` |
| Linux | inside install dir | app data dir | `~/.kaiteyo`, `$XDG_DATA_HOME/kaiteyo` |
| Android | APK asset | app-private SQLite | — |
| iOS | app bundle | app sandbox | — |

> The exact paths are resolved by platform file handlers (`PlatformFile`, backup archive
> handlers, etc.). The installer/uninstaller never deletes user data without explicit
> confirmation (see `installer/README.md`).

## Data classification

| Data | Category | Owned by | Notes |
|---|---|---|---|
| Kanji/kana/vocab dictionary content | Bundled (generated) | Third-party datasets (see SOURCES.md) | Generated by KJD; read-only |
| Stroke-order data (KanjiVG) | Bundled (generated) | KanjiVG (CC BY-SA 3.0) | Attached at KJD build time when `--vg` is given |
| TTS voice assets (Neural2B kana) | Downloaded on first build | Google Neural2 voices (per asset licensing) | `kjd`/AppAssets; wav for desktop/iOS, opus for Android |
| Decks, cards, FSRS state | User-created | User | UserDataDatabase |
| Review history, statistics | User-created | User | UserDataDatabase + stats tables |
| Tags, flags, suspend/bury state | User-created | User | On cards/decks |
| Deck archive state | User-created | User | `is_archived` columns |
| Writing evaluation data | Generated | Kaiteyo | Stroke evaluation results; per-session |
| Media metadata, bookmarks, subtitles (desktop) | User-created | User | `~/.kaiteyo` JSON |
| Mined cards, mining records | User-created | User | Desktop library + UserDataDatabase |
| Imported dictionaries (desktop) | User-created | User (content licensed to them) | `~/.kaiteyo/dictionaries/` + index |
| Settings / preferences | User-created | User | DataStore + `settings.json` |
| Account tokens | User-created (synced) | User | OAuth tokens in `TokenVault` |
| Sync snapshots | Synchronized | User | Private GitHub gist when sync enabled |
| Backup archives | User-created | User | Exported by BackupManager |
| Cache (search index, thumbnails) | Cached | Kaiteyo | Regenerable; safe to delete |
| Demo seed data (desktop) | Generated | Kaiteyo | First-run only, `DemoData.kt` |

## Data ownership & licensing implications

- **Bundled language data is third-party licensed** and must keep its attribution — see
  [`SOURCES.md`](SOURCES.md) and `legal/THIRD_PARTY_NOTICES.md`. The KJD pipeline emits a
  provenance/attribution manifest (`THIRD_PARTY_DATA.json` / `.md`) with every generated
  database.
- **User-created data belongs to the user.** Import/export, backup/restore, and sync
  exist so that data is never locked in.
- **Imported content** (decks, `.apkg` files, dictionaries) stays on-device; HTML is
  sanitized before rendering (see `SECURITY.md`).
